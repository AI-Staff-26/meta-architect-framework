# 🧠 Context Management — Управление Контекстом LLM

<purpose>
Контекст — ограниченный ресурс. Используй стратегически, а не как свалку.
</purpose>

---

## Ключевые Принципы

### 1. Turn Limit (Правило 10-15 шагов)

> **После 10-15 шагов качество деградирует.**

| Признаки деградации | Действие |
|---------------------|----------|
| Повторение одних и тех же ошибок | STOP → restart |
| Забывает ограничения из начала сессии | → Context.md snapshot |
| Путает файлы или переменные | → Сократить загруженный контекст |
| Предлагает уже отвергнутые решения | → Обновить Context.md с решениями |

**Правило:** Лучше 3 чистых сессии по 5 шагов, чем 1 грязная на 15 шагов.

---

### 2. Меньше, но Релевантнее

> **Не загружай всё. Загружай только то, что нужно для СЛЕДУЮЩЕГО решения.**

```
❌ Плохо:
- Загрузить весь проект "на всякий случай"
- Открыть 10 файлов "для контекста"
- Скопировать всю документацию в промпт

✅ Хорошо:
- Загрузить 1-2 файла, необходимых для текущего шага
- Использовать Context.md как сжатый snapshot
- Агрессивно фильтровать: "Нужно ли это для ЭТОГО шага?"
```

**Правило 40-50%:** Держи контекст заполненным максимум на 40-50%. Оставляй место для ответа и неожиданностей.

---

### 3. Lost in the Middle (Потеря в Середине)

> **LLM лучше помнят начало и конец промпта. Середина "размывается".**

```
Структура промпта:

┌─────────────────────────────┐
│ 🔴 КРИТИЧНОЕ (начало)       │  ← Цель, главные ограничения
├─────────────────────────────┤
│ 🟡 Детали (середина)        │  ← Контекст, примеры, справка
├─────────────────────────────┤
│ 🔴 КРИТИЧНОЕ (конец)        │  ← Acceptance Criteria, запреты
└─────────────────────────────┘
```

**Практика:**
- Главное ограничение → дублируй в начале И в конце
- Секция ❌ (запреты) → всегда в конце промпта
- Acceptance Criteria → последний блок перед "Output Format"

---

### 4. Context.md как Snapshot

> **Когда контекст переполняется — создай snapshot и начни чистую сессию.**

**Структура Context.md:**

```markdown
# Context Snapshot
*Updated: YYYY-MM-DD HH:MM*

## Текущая Цель
[1-2 предложения: что делаем]

## Принятые Решения
- [Решение 1]: [почему]
- [Решение 2]: [почему]

## Ключевые Файлы
- `path/to/file.ts` — [зачем важен]

## Активные Ограничения
- ❌ [запрет 1]
- ❌ [запрет 2]

## Следующий Шаг
[Конкретное действие]
```

**~200 слов максимум.** Это snapshot, не документация.

---

### 5. Когда Делать Restart

**Обязательный restart:**
- [ ] >10 шагов в сессии
- [ ] @coder повторяет ошибки (>2 раза)
- [ ] Забыты ограничения из начала
- [ ] Путаница в файлах/переменных
- [ ] Накопились костыли/workarounds

**Протокол restart:**
1. STOP текущую работу
2. Обновить `Context.md` (snapshot текущего состояния)
3. Начать новую сессию
4. Первый промпт: загрузить `Context.md` + целевые файлы
5. Продолжить с чистого состояния

## Антипаттерны

| Антипаттерн | Почему плохо | Как исправить |
|-------------|--------------|---------------|
| **Context Dump** — загрузить всё | Размывает фокус, теряется важное | Загружать только для текущего шага |
| **Session Marathon** — 20+ шагов | Деградация качества | Restart после 10-15 |
| **Hope-driven Context** — "авось пригодится" | Засоряет контекст | Агрессивная фильтрация |
| **No Snapshot** — потерял контекст | Приходится восстанавливать | Регулярные Context.md |
| **Middle Stuffing** — важное в середину | LLM забудет | Важное в начало/конец |

- [ ] Критичное в начале И конце промпта?
- [ ] Секция ❌ в конце?
- [ ] Сессия < 10 шагов?
- [ ] Context.md актуален?

