# 🎯 Scope Control — Контроль Скоупа

<purpose>
Scope creep — главный убийца проектов. Контролируй скоуп жёстко.
</purpose>

---

## Ключевые Принципы

### 1. Explicit Scope = Safe Scope

> **Если скоуп не записан — его не существует.**

```markdown
❌ Плохо:
- "Сделаем авторизацию"
- "Добавим пользователей"
- "Интегрируем с API"

✅ Хорошо:
- "Авторизация: email/password, JWT, refresh token. БЕЗ OAuth."
- "User: email, passwordHash, createdAt. БЕЗ профиля, БЕЗ аватара."
- "API: только GET /items, POST /items. БЕЗ search, БЕЗ pagination."
```

**Правило:** Что не указано в scope — явно вне scope.

---

### 2. In/Out Scope List

> **Каждый scope документ содержит две колонки: IN и OUT.**

```markdown
## Scope: Авторизация MVP

### ✅ IN Scope
- Login с email/password
- JWT access token (1h)
- Refresh token (7d)
- Logout (invalidate token)

### ❌ OUT Scope
- OAuth (Google, GitHub)
- 2FA
- "Забыли пароль"
- Email verification
- Session management (multiple devices)
- Rate limiting
- Brute force protection

### 🔮 Future (v2)
- OAuth integration
- 2FA via TOTP
```

**Правило OUT Scope:** Если задача граничит с OUT scope — STOP и вернись к Meta-Architect.

---

### 3. Scope Gates (Ворота Скоупа)

> **Добавление в скоуп требует прохождения через Gate.**

```
┌─────────────────────────────────────────────┐
│ Новый запрос/идея                            │
└─────────────────┬───────────────────────────┘
                  ▼
┌─────────────────────────────────────────────┐
│ GATE 1: Соответствует текущей цели?         │
│         НЕТ → Отклонить или отложить        │
└─────────────────┬───────────────────────────┘
                  ▼ ДА
┌─────────────────────────────────────────────┐
│ GATE 2: Критично для MVP/текущей итерации?  │
│         НЕТ → В Backlog / Future            │
└─────────────────┬───────────────────────────┘
                  ▼ ДА
┌─────────────────────────────────────────────┐
│ GATE 3: Влияет на дедлайн/ресурсы?          │
│         ДА → Эскалация к стейкхолдерам      │
└─────────────────┬───────────────────────────┘
                  ▼ НЕТ
┌─────────────────────────────────────────────┐
│ Добавить в scope с документацией            │
└─────────────────────────────────────────────┘
```

**Правило:** Никакого "добавим по ходу". Всё через Gates.

---

### 4. Scope Freeze Points

> **На определённых этапах скоуп замораживается.**

| Этап | Scope Status | Допустимые Изменения |
|------|--------------|----------------------|
| Ideation | 🟢 Открыт | Любые |
| Requirements | 🟡 Ограничен | Уточнения, не расширения |
| Design | 🟡 Ограничен | Технические детали |
| Implementation | 🔴 Заморожен | Только критические баги |
| Testing | 🔴 Заморожен | Только блокирующие баги |

**Срочное изменение:** Требует подтверждения от Architect + оценку влияния на timeline.

---

### 5. Scope Creep Сигналы

> **Распознай creep до того, как он затопит проект.**

**Ранние сигналы:**
```
⚠️ "А может заодно..."
⚠️ "Было бы неплохо добавить..."
⚠️ "Раз уж мы здесь, давай..."
⚠️ "Пользователям точно понадобится..."
⚠️ "Это же быстро сделать..."
⚠️ "Небольшое улучшение..."
```

**Признаки активного creep:**
```
🔴 Задача "разрасталась" в процессе
🔴 Появились новые файлы не из плана
🔴 @coder спрашивает про функционал не из ТЗ
🔴 Deadline двигается без изменения scope
🔴 "Небольшие" задачи занимают дни
```

**Реакция:**
1. STOP текущую работу
2. Вернуться к scope документу
3. Классифицировать: IN/OUT/FUTURE
4. Продолжить только после уточнения

## Протоколы

### Протокол: Scope Clarification

```markdown
Когда @coder/кто-либо предлагает что-то вне scope:

1. STOP — не реализовывай
2. Спроси:
   - "Это критично для текущего MVP?"
   - "Что будет, если сделаем в v2?"
   - "Какой impact на timeline?"
3. Классифицируй:
   - ✅ IN → продолжить
   - ❌ OUT → reject с обоснованием
   - 🔮 FUTURE → добавить в backlog
4. Обнови scope документ
5. Продолжи работу
```

### Протокол: Scope Change Request

```markdown
При необходимости изменить scope:

1. Опиши изменение:
   - Что добавляется / убирается
   - Почему критично сейчас
   - Impact на timeline / ресурсы

2. Пройди Gates:
   - [ ] Соответствует цели?
   - [ ] Критично для MVP?
   - [ ] Impact оценён?

3. Получи подтверждение:
   - От Architect (технические изменения)
   - От Stakeholder (бизнес изменения)

4. Обнови документы:
   - Scope документ
   - Plan (если влияет на задачи)
   - Timeline (если влияет на сроки)

5. Проинформируй команду
```

### Протокол: @coder Scope Check

```markdown
Перед отправкой задачи @coder:

- [ ] Задача соответствует IN Scope?
- [ ] Нет намёков на OUT Scope функционал?
- [ ] Acceptance Criteria в рамках scope?
- [ ] Ограничения (❌) явно указаны?

После получения результата от @coder:

- [ ] Реализация соответствует scope?
- [ ] Нет "побочных улучшений"?
- [ ] Нет доп. файлов/функций вне ТЗ?
```

## Шаблон Scope Документа

```markdown
# Scope: [Feature/Project Name]

## Версия
- v1.0 | Updated: YYYY-MM-DD
- Status: 🟢 Открыт / 🟡 Ограничен / 🔴 Заморожен

## Цель
[1-2 предложения: что делаем и зачем]

## ✅ IN Scope

### Must Have (критично)
- [ ] Функция 1 — [краткое описание]
- [ ] Функция 2 — [краткое описание]

### Should Have (желательно)
- [ ] Функция 3 — [описание, при условии X]

## ❌ OUT Scope
- Функция A — причина: [почему вне scope]
- Функция B — причина: [связано с X, делаем в v2]
- Оптимизация — причина: [преждевременно]

## 🔮 Future (следующие итерации)
- v2: OAuth, 2FA
- v3: Admin panel
- Backlog: Rate limiting, Audit log

## Ограничения
- Timeline: [deadline]
- Ресурсы: [команда/бюджет]
- Технические: [ограничения стека]

## Change Log
| Дата | Изменение | Причина | Approver |
|------|-----------|---------|----------|
| YYYY-MM-DD | Initial scope | - | @architect |
```

## Антипаттерны

| Антипаттерн | Признак | Как избежать |
|-------------|---------|--------------|
| **Gold Plating** | "Сделаю лучше чем просили" | Строго следуй scope |
| **Unwritten Scope** | "Мы же обсуждали" | Всё в документ |
| **Scope Silence** | Никто не говорит "нет" | Явный OUT Scope |
| **Infinite Backlog** | "Когда-нибудь сделаем" | Приоритизация и выброс |
| **Feature Creep** | +1 маленькая фича | Scope Gates |
| **Tech Scope** | "Перепишу заодно" | Отдельная задача |

## Quick Reference

```
Scope Control = Дисциплина доставки

Правила:
1. Записано → существует. Не записано → нет.
2. IN/OUT/FUTURE — три категории всегда
3. Scope Gates для любого добавления
4. Freeze points по этапам
5. Сигналы creep → STOP и уточни
```
