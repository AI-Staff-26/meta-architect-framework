# 1. OODA LOOP

## Источник
**Джон Бойд** — военный стратег, «отец» истребителя F-16.

## Суть
Побеждает не тот, у кого лучше план, а тот, кто быстрее проходит цикл принятия решений.

## Цикл

```
OBSERVE (Наблюдай)
    ↓
ORIENT (Ориентируйся)
    ↓
DECIDE (Решай)
    ↓
ACT (Действуй)
    ↓
[Повторить]
```

## Детализация

**OBSERVE (Наблюдай):**
- Факты, данные, сигналы
- Что изменилось?
- Новая информация?

**ORIENT (Ориентируйся):** ← Самый важный этап
- Что это значит в контексте?
- Какой домен (Cynefin)?
- Интересы игроков
- Мои ментальные модели применимы?
- Культурный контекст

**DECIDE (Решай):**
- Какие варианты?
- Какой критерий выбора?
- Выбор линии действия

**ACT (Действуй):**
- Конкретное действие
- Триггеры для пересмотра

## Применение

**В бизнесе:**
```
OBSERVE: Конкурент снизил цены на 20%
ORIENT: Это демпинг или новая эффективность? Как отреагируют клиенты?
DECIDE: Держим цены, усиливаем сервис (или матчим цену)
ACT: Запускаем кампанию «Качество стоит того»
→ Снова OBSERVE: как реагируют клиенты?
```

**В переговорах:**
```
OBSERVE: Оппонент напрягся при упоминании сроков
ORIENT: Сроки для него критичны? Или он блефует?
DECIDE: Надавить на сроки как leverage
ACT: «Я понимаю, что время для вас важно...»
```

## Ключевой инсайт
Тот, кто проходит OODA быстрее, создаёт хаос для оппонента (он не успевает реагировать). Разорви его OODA-цикл — и он потеряет.

# 2. BACKWARD INDUCTION (Обратная индукция)

## Источник
Теория игр, гроссмейстеры.

## Суть
Начни с конца. Определи финальное состояние (Z), затем отматывай назад до текущего момента (A).

## Алгоритм

```
1. Определи Z — как выглядит победа?
2. Спроси: «Что должно произойти на шаге Y, чтобы Z стало неизбежным?»
3. Спроси: «Что должно быть на X, чтобы Y стало возможным?»
4. Продолжай до текущего момента A
5. Первый шаг — запускает цепочку
```

## Пример

**Цель (Z):** Получить инвестицию $1M

```
Z: Инвестор подписывает чек
    ← Y: Инвестор убеждён в команде, рынке и модели
    ← X: Успешная презентация + due diligence пройдён
    ← W: Meeting с партнёром фонда
    ← V: Тёплое интро от кого-то из его портфеля
    ← U: Найти общего знакомого в портфеле
    ← T: Изучить портфель фонда
    ← A (сегодня): Составить список фондов и их портфелей
```

## Ключевой вопрос
«Какое состояние мира делает мою победу неизбежной?»

# 3. SECOND-ORDER THINKING (Мышление второго порядка)

## Источник
Howard Marks, Warren Buffett, Ray Dalio.

## Суть
Каждое решение имеет последствия. Последствия имеют свои последствия. Думай на 2-3 шага вперёд.

## Формула

```
РЕШЕНИЕ
    ↓
Последствие 1-го порядка (что произойдёт сразу?)
    ↓
Последствие 2-го порядка (как отреагируют другие?)
    ↓
Последствие 3-го порядка (системные эффекты?)
```

## Пример

**Решение:** Уволить 20% команды для сокращения расходов

```
Порядок 1: Расходы снизятся на $X
Порядок 2: Перегруз оставшихся → выгорание → уволятся лучшие
Порядок 3: Потеря ключевых людей → падение качества → потеря клиентов
```

**Вывод:** Прямая экономия может обойтись дороже.

## Вопросы для каждого уровня

| Уровень | Вопрос |
|:--------|:-------|
| 1 | Что произойдёт сразу? |
| 2 | Как отреагируют другие игроки? |
| 3 | Какие вторичные эффекты возникнут? |

## Правило
Для каждой ключевой вехи — минимум 3 уровня «И что потом?»

# 4. RED TEAM (Красная команда)

## Источник
Военная разведка, кибербезопасность.

## Суть
Атакуй собственный план. Попытайся его уничтожить, чтобы найти уязвимости до того, как это сделает враг.

## Протокол

## RED TEAM АНАЛИЗ

**План/Стратегия:** [Что анализируем]

**Я — Враг. Мои цели:**
- Уничтожить этот план
- Использовать слабости
- Нанести максимальный урон

**Векторы атаки:**

1. **Слабое звено:** [Какой элемент плана самый уязвимый?]
   - Атака: [...]
   - Ущерб: [...]

2. **Информационная атака:** [Какой информацией можно навредить?]
   - Атака: [...]
   - Ущерб: [...]

3. **Чёрный лебедь:** [Какое редкое событие убьёт план?]
   - Событие: [...]
   - Ущерб: [...]

**Патчи (как защититься):**
- [Защита от атаки 1]
- [Защита от атаки 2]
- [Защита от чёрного лебедя]

## 3 Персоны для Red Team

1. **Агрессивный конкурент:** Что бы сделал, чтобы украсть рынок?
2. **Регулятор/Враг:** Что бы сделал, чтобы закрыть бизнес?
3. **Предатель внутри:** Что бы сделал инсайдер, чтобы навредить?

# 5. CYNEFIN FRAMEWORK

## Источник
Dave Snowden, IBM.

## Суть
Разные ситуации требуют разных способов принятия решений. Сначала определи домен.

## 4 Домена

```
┌─────────────────────┬─────────────────────┐
│      COMPLEX        │    COMPLICATED      │
│  (Сложный-эмердж.)  │     (Сложный)       │
│                     │                     │
│  Probe-Sense-Respond│ Sense-Analyze-Respond│
│  Эксперимент        │  Экспертный анализ  │
│  Паттерны постфактум│  Есть правильный    │
│                     │  ответ              │
├─────────────────────┼─────────────────────┤
│      CHAOTIC        │      SIMPLE         │
│    (Хаотичный)      │    (Очевидный)      │
│                     │                     │
│  Act-Sense-Respond  │ Sense-Categorize-   │
│  Сначала действуй   │     Respond         │
│  Стабилизируй       │ Best practices      │
└─────────────────────┴─────────────────────┘
```

## Описание доменов

| Домен | Характеристика | Подход |
|:------|:---------------|:-------|
| **Simple** | Причина→следствие очевидны. Есть best practice. | Увидел → категоризировал → применил правило |
| **Complicated** | Причина→следствие существует, но не очевидна. Нужен эксперт. | Анализ → несколько правильных ответов → выбор |
| **Complex** | Причина→следствие видна только постфактум. Непредсказуемо. | Безопасные эксперименты → смотри, что работает → масштабируй |
| **Chaotic** | Нет видимой причинности. Кризис, всё горит. | Действуй сначала → стабилизируй → потом анализируй |

## Ключевые ошибки

- Применять Simple-подход к Complex-ситуации (жёсткий план к стартапу)
- Анализировать в Chaotic (паралич в кризисе)
- Экспериментировать в Simple (тратить время на очевидное)

# 6. DECISION TREES (Деревья решений)

## Суть
Визуализация ветвлений решений и их последствий.

## Формат

```
РЕШЕНИЕ
    │
    ├─ ЕСЛИ [условие A]
    │       │
    │       ├─ Результат A1
    │       └─ Результат A2
    │
    └─ ЕСЛИ [условие B]
            │
            ├─ Результат B1
            └─ Результат B2
```

## Шаблон для планирования

## DECISION TREE: [Ситуация]

**Развилка 1:** [Вопрос/условие]

Если [A]:
  → Действие: [...]
  → Ожидаемый результат: [...]
  → Следующая развилка: [...]

Если [B]:
  → Действие: [...]
  → Ожидаемый результат: [...]
  → Следующая развилка: [...]

**Триггеры пересмотра:**
- [При каком условии переоценить весь план]

## Пример: Переговоры

```
Предлагаю цену X
    │
    ├─ ЕСЛИ согласится
    │       → Закрываю сделку
    │       → Следующий шаг: договор
    │
    └─ ЕСЛИ отказ
            │
            ├─ ЕСЛИ причина — цена
            │       → Калиброванный вопрос: «Как мы можем найти решение?»
            │       → Предложить альтернативу (рассрочка, меньший scope)
            │
            └─ ЕСЛИ причина — не наш приоритет
                    → Квалифицировать: когда вернуться?
                    → Или выход: не наш клиент
```
