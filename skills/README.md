# Skills — Meta-Architect Framework

Указатель. Каждый скил описывает себя сам — в поле `description` своего `SKILL.md`; здесь только имя и повод к нему обратиться. Описание живёт в одном месте, иначе копии расходятся и агент верит той, которую прочитал последней.

Вызов по имени. Правила, по которым эти файлы пишутся, — в `authoring-skills`.

---

## Метод

Ядро фреймворка: то, как ведётся работа, независимо от предметной области.

| Скил | Когда |
|---|---|
| `grilling` | Требования размыты — интервью до полной ясности. Базовый примитив, его вызывают другие скилы |
| `prior-art` | Строим то, что может уже существовать: зависимость, референс-реализация или настоящий пробел |
| `tdd` | Цикл red → green, вертикальными срезами. И критерий того, что тест хорош |
| `verification-budget` | Сколько проверять: уровни риска, лестница прогонов, одна команда — один короткий ответ, бюджет агентов-проверяющих |
| `codebase-design` | Проектирование модуля и границы: глубина, шов, адаптер, локальность |
| `memory-keeping` | Форматы всего, что лежит в `memory/` — PROFILE, FACTS, DECISIONS, ADR, repo-wiki, отчёты |
| `authoring-skills` | Написание и правка текста фреймворка: скилы, агенты, правила |
| `architectural-planning` | Делегирование: шаблоны промптов, декомпозиция, контроль скоупа, handoff |
| `framework-knowledge-base` | Вопросы о самом фреймворке — роли, потоки, troubleshooting |
| `onboarding` | Нет `memory/PROFILE.md` — инициализация проекта и памяти |

## Workflow — по типу работы

| Скил | Когда |
|---|---|
| `workflow-feature` | Новая функциональность |
| `workflow-debugging` | Сломалось, падает, флакует, тормозит — сначала петля обратной связи |
| `forensic-investigation` | Агент ходит по кругу: правки ломают соседнее, патчи копятся; ревью каждый раз находит соседний путь — карта путей |
| `workflow-refactoring` | Улучшение кода без изменения поведения |
| `workflow-architecture-change` | Смена слоёв, паттерна, контрактов — всегда 🔴 |
| `workflow-requirements-interview` | Что именно нужно — территория требований и шаблон Requirements.md |
| `workflow-new-project` | Проект с нуля: требования, стек под защиту, первый сквозной путь |
| `workflow-legacy-analysis` | Незнакомая система без конкретного симптома |
| `workflow-ai-session` | Контекст деградировал — снимок и чистый рестарт |
| `workflow-devops` | Инфраструктура: окружение, контейнеры, CI/CD, деплой, секреты, наблюдаемость |
| `workflow-ui-build-order` | Порядок сборки UI: тонкий фундамент → вертикальные срезы → проход на консистентность |

## Чеклисты — ворота качества

| Скил | Когда |
|---|---|
| `checklist-code-review` | Ревью изменений по трём осям: Standards, Spec, Security |
| `checklist-security` | Изменение, критичное по безопасности |
| `checklist-infra` | Инфраструктура — до деплоя и при ревью infra-as-code |
| `checklist-release` | Перед релизом в продакшн: Go / No-Go |
| `checklist-ux-design` | UI-фича — до реализации, чтобы не получить «ванильный» интерфейс |
| `checklist-ux-review` | Проверка реализованного UI в работе: все состояния, клавиатура, контраст, ширины |
| `checklist-phase-completion` | Переход между фазами: что должно быть готово |

## Архитектурные паттерны

| Скил | Когда |
|---|---|
| `pattern-clean-architecture` | Правило зависимостей: импорты внутрь, слои перестают быть папками |
| `pattern-modular-monolith` | Граница `api`/`internal`, которую проверяет сборка; путь к извлечению модуля |
| `pattern-multi-tenant` | Изоляция арендаторов как инвариант: инвентарь путей, где tenant теряется |
| `pattern-rbac` | Единица проверки — право, а не роль: грамматика `resource:action:scope`, области |
| `pattern-feature-flags` | Флаг как ветка в проде: раскатка, аварийный выключатель, entitlements по тарифу |
