# ✅ Code Review Checklist — Чеклист Ревью Кода

<purpose>
Качественные ворота для @reviewer. Используй для каждого ревью после @coder.
</purpose>

## Быстрый Обзор

| Категория | Критичность |
|-----------|-------------|
| 🔴 Функциональность | Блокирующая |
| 🔴 Безопасность | Блокирующая |
| 🟠 Архитектура | Высокая |
| 🟡 Качество кода | Средняя |
| 🟢 Стиль | Низкая |

---

## 🔴 Функциональность (Блокирует)

### Соответствие требованиям

- [ ] Код решает поставленную задачу (соответствует Plan.md)
- [ ] Все Acceptance Criteria из задачи выполнены
- [ ] Edge cases обработаны
- [ ] Нет рег

рессий в существующей функциональности

### Тестирование

- [ ] Тесты написаны для новой функциональности
- [ ] Тесты покрывают happy path
- [ ] Тесты покрывают edge cases / error handling
- [ ] Все существующие тесты проходят
- [ ] Build проходит успешно

---

## 🔴 Безопасность (Блокирует)

### Входные данные

- [ ] Все входные данные валидируются
- [ ] Используется whitelist-подход (не blacklist)
- [ ] Нет доверия к user input

### Авторизация

- [ ] Проверки доступа на месте
- [ ] Нет обхода auth/authz
- [ ] Нет privilege escalation

### Секреты

- [ ] Нет hardcoded credentials
- [ ] Нет secrets в логах
- [ ] Нет PII в логах
- [ ] Конфиденциальные данные защищены

### Уязвимости

- [ ] Нет SQL injection
- [ ] Нет XSS уязвимостей
- [ ] Нет path traversal
- [ ] Нет command injection
- [ ] Безопасная десериализация

> 💡 Детальный чеклист: `checklists/security.md`

---

## 🟠 Архитектура (Высокая)

### Соответствие архитектуре

- [ ] Следует Architecture.md
- [ ] Границы слоёв не нарушены
- [ ] Зависимости направлены правильно (внутрь)
- [ ] Нет circular dependencies

### Контракты

- [ ] API контракты не нарушены (breaking changes согласованы)
- [ ] Типы/интерфейсы соответствуют договорённостям
- [ ] Версионирование API соблюдено (если применимо)

### Масштабируемость

- [ ] Нет N+1 queries
- [ ] Нет блокирующих операций в критических путях
- [ ] Ресурсоёмкие операции оптимизированы

---

## 🟡 Качество кода (Средняя)

### Читаемость

- [ ] Код самодокументирующийся
- [ ] Нейминг понятный и консистентный
- [ ] Сложная логика прокомментирована (WHY, не WHAT)
- [ ] Нет magic numbers/strings

### Поддерживаемость

- [ ] DRY — нет избыточного дублирования
- [ ] SOLID принципы соблюдены (разумно)
- [ ] Нет god-objects / god-methods
- [ ] Разумный уровень абстракции

### Error Handling

- [ ] Ошибки обрабатываются явно
- [ ] Нет пустых catch блоков
- [ ] Ошибки логируются с контекстом
- [ ] Graceful degradation (где применимо)

---

## 🟢 Стиль (Низкая)

### Форматирование

- [ ] Linter проходит без ошибок
- [ ] Форматирование консистентно с проектом
- [ ] Соответствует framework rules

### Чистота

- [ ] Нет закомментированного кода
- [ ] Нет TODO без тикета
- [ ] Нет console.log / debug вывода
- [ ] Нет мёртвого кода

---

## Процесс Ревью

### Перед ревью

1. Загрузить контекст:
   - `/docs/prompt-*.md` — что планировалось
   - `rules/meta-architect-framework.md` — правила фреймворка
   - `memory/repo-wiki/overview.md` — архитектурные границы

2. Понять scope изменений

### Во время ревью

1. Проверить блокирующие категории (🔴) первыми
2. Документировать находки
3. Классифицировать severity

### Результат ревью

**PASS:**

```markdown
## ✅ Review PASS

**Проверено:**
- [x] Функциональность
- [x] Безопасность  
- [x] Архитектура
- [x] Качество кода

**Комментарии:**
[Опциональные улучшения, не блокирующие]

🛑 STOP — control returns to @meta-architect
```

**FAIL:**

```markdown
## ❌ Review FAIL

**Блокирующие проблемы:**
1. [Категория]: [Описание проблемы]
   - Файл: `path/to/file`
   - Строка: X-Y
   - Требуется: [что нужно исправить]

**Severity:** 🔴 Critical / 🟠 High / 🟡 Medium

🛑 STOP — control returns to @meta-architect
```

---

## Severity Guide

| Level | Критерий | Действие |
|-------|----------|----------|
| 🔴 Critical | Безопасность, потеря данных, не работает | FAIL — немедленное исправление |
| 🟠 High | Нарушение архитектуры, регрессии | FAIL — исправить перед merge |
| 🟡 Medium | Качество кода, поддерживаемость | PASS с условием — исправить в follow-up |
| 🟢 Low | Стиль, мелочи | PASS — опциональные улучшения |

---

## Quick Reference

```
Ревью Приоритеты:

1. 🔴 Работает? (Acceptance Criteria)
2. 🔴 Безопасно? (No vulnerabilities)
3. 🟠 Архитектурно? (Boundaries, contracts)
4. 🟡 Качественно? (Maintainable, readable)
5. 🟢 Красиво? (Style, formatting)

Результат:
- PASS → @meta-architect continues
- FAIL → @meta-architect analyzes → @coder fixes
```
